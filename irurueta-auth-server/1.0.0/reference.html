Reference

This documentation was generated with the assistance of AI. Please report any inaccuracies.

The Documentation workflow (.github/workflows/docs.yml) rebuilds and tests the whole reactor on every push to main, generates the Maven site and publishes it to GitHub Pages next to this documentation, so the reports below always describe the latest main. SonarCloud analyses every push and pull request when the SONAR_TOKEN secret is set (organization albertoirurueta, project albertoirurueta_irurueta-auth-server).

Generated Reports

Report Description

Javadoc

API reference of every module in one place, generated by the Maven Javadoc plugin (aggregate-no-fork). Each module’s own Javadoc is also linked from its module page.

JaCoCo (aggregated)

Coverage of unit and integration tests aggregated over every module by the coverage module. This is the bundle the 80% line / 70% branch gate checks and the jacoco.xml SonarCloud reads.

Surefire, Failsafe

Unit (*Test) and integration (*IT) test results. Every module has its own surefire.html (and failsafe.html when it has integration tests); the links open the auth-server composition root, which holds most integration tests.

Checkstyle, PMD, CPD, SpotBugs

Static analysis results, one set per module (shown for auth-server/api/web; open Modules in the Maven site for the others). They are the same rules that fail ./mvnw verify.

Source cross-reference (JXR)

Browsable, line-numbered sources that the reports above link to.

API contract of auth-server, HTML

The OpenAPI contract apis/auth-server/rest-server/auth-server-api-v1.yaml (account, client and key administration under /api/**), from which the interfaces and DTOs of auth-server/api/web are generated, and its HTML rendering. OpenApiDriftIT fails when the running application no longer matches it.

Pages contract of auth-server, HTML

The OpenAPI contract apis/auth-server/web-pages/auth-server-pages-v1.yaml of the server-rendered pages (/login, /login/second-factor, /login/second-factor/recovery-codes, /account/passkeys, /login/ott, /login/ott/confirm, /account/phone, /oauth2/consent, /logout, each answering text/html), from which the interfaces of the page controllers are generated, and its HTML rendering. OpenApiDriftIT compares it with the springdoc group pages.

API contract of resource-server, HTML

The OpenAPI contract of resource-server (documents API), generated into resource-server/api/web and guarded by its own drift test. The BFF generates its client of the resource server from it too (bff/infrastructure/resourceserver).

API contract of bff, HTML

The OpenAPI contract of the BFF’s endpoints (/bff/user, /bff/login and the documents API /api/documents; POST /bff/logout is answered by Spring Security and is not part of it), generated into bff/api/web and guarded by its own drift test. The behaviour is described in Login pages and the BFF.

Generating the reports locally

./mvnw verify writes the raw results (<module>/target/surefire-reports/, failsafe-reports/, site/jacoco/, checkstyle-result.xml, pmd.xml, spotbugsXml.xml and coverage/target/site/jacoco-aggregate/). For the browsable site exactly as it is published, run:

./mvnw install
./mvnw site site:stage -DskipTests   # written to target/staging

The aggregated Javadoc resolves the modules from the local repository, which is why the build runs install first.

Configuration properties

The auth-server properties below are the ones that change security behavior; each defaults to the safe value.

Property Default Meaning

authserver.api.audience

auth-server

Audience a bearer token must list to call /api/**; the seeded clients get it too. See Tokens and signing keys.

authserver.clients.bff.redirect-uris, authserver.clients.spa-public.redirect-uris

empty

Redirect URIs of the default clients; a client is seeded only when they are set. The dev profile sets the local ones. See Registered clients.

authserver.clients.bff-secret

empty (AUTHSERVER_BFF_CLIENT_SECRET)

Secret of the seeded bff client; without it the client is not seeded.

authserver.account.rate-limit.*

enabled, 20 per client and 5 per address in 15 minutes

Rate limiting of the unauthenticated account endpoints. See Passwords and accounts.

authserver.account.cleanup.cron

0 30 * * * *

Schedule of the clean-up of expired account tokens.

authserver.keys.retention, authserver.keys.clock-skew

PT2H, PT60S

Minimum retention of a retired signing key and the clock skew added to the longest signed-token lifetime.

authserver.tokens.cleanup.abandoned-after

P1D

Age after which an authorization that never got a token is deleted.

Build gates

./mvnw -B clean verify fails when any of these fails:

Gate Rule

Checkstyle

checkstyle.xml, violationSeverity=warning, test sources included (full Javadoc, final parameters, no magic numbers). Runs at the validate phase.

PMD and CPD

Static analysis and copy-paste detection, at verify.

SpotBugs

threshold=Medium, effort=Max; exclusions only in spotbugs-exclude.xml, each with a reason.

JaCoCo

80% line and 70% branch coverage on the bundle aggregated by the coverage module (unit plus integration tests). Never lowered: add tests instead.

Enforcer

Java [21,26), Maven 3.9 or newer and the per-module bannedDependencies rules of the hexagonal layout.

ArchUnit

HexagonalArchitectureTest in the boot module of each application.

SonarCloud

The Build and test workflow runs ./mvnw -B -ntp sonar:sonar after verify when the SONAR_TOKEN secret is set. The project properties (sonar.organization, sonar.projectKey, sonar.host.url and the aggregated JaCoCo report path) live in the root pom.xml. That workflow never deploys anything; only the Documentation workflow publishes, and only the documentation.
