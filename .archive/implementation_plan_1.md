# Implementation plan: Walking skeleton (issue #1)

## Task summary

Turn the repository skeleton into a walking skeleton: all four applications run end to end with username + password
sign-in. Add PostgreSQL persistence with Flyway, local services (`compose.yaml`), a Testcontainers test harness, the
`auth-server` extension points that let later issues (#2–#8) work in parallel, tooling (springdoc-openapi with an
`openapi/` drift test, an `e2e-tests` module) and the Antora Collector configuration that exposes the code to the docs
site.

Source: GitHub issue #1
Base branch: main

Choices made (challenge them in review):
- **E2E tool: Playwright for Java.** It manages its own browsers and auto-waits, so the smoke test needs no driver
  setup and is less flaky than Selenium. Record this one-line rationale in `e2e-tests/pom.xml` and in `CLAUDE.md`.
- **Shared test harness: a small `test-support` module** (compile scope on the test classpath of the other modules)
  rather than a test-jar, so each module depends on it with a plain `<scope>test</scope>` dependency.
- **Flyway:** `V100`–`V199` only, `classpath:db/migration`. `auth-server` owns the OAuth/user tables; `bff` and
  `resource-server` get persistence only where they need it (the BFF session store is deferred to #3; their `*IT`
  tests start PostgreSQL through the shared base).
- **Database per application:** `compose.yaml` creates one database per app through an init script.
- **Temporary pieces** (`DelegatingPasswordEncoder`, in-memory RSA `JWKSource`) carry a `// TEMPORARY: replaced in #2`
  comment so #2 can find them.

Open clarifications: none

## Current code state

- Maven reactor (Spring Boot parent 4.1.2, Java 21): `auth-server`, `bff`, `resource-server`, `service-client`. The root
  `pom.xml` declares plugin versions as properties, enforcer, Failsafe (`*IT`), JaCoCo and report-only quality plugins;
  there is **no** `dependencyManagement` yet.
- Each module has only `<Name>Application.java`, `package-info.java`, a minimal `application.yml` (name, port, actuator)
  and a `<Name>ApplicationTest` context-load test. Ports: auth-server 9000, bff 8080, resource-server 8081.
- `auth-server/pom.xml`: webmvc, authorization-server, thymeleaf (+ springsecurity extras), validation, actuator
  starters. `bff/pom.xml`: webmvc, oauth2-client, actuator. `resource-server` and `service-client` poms: re-read
  before editing (not yet inspected).
- Not present yet: JDBC/Flyway/PostgreSQL, Testcontainers, `spring-boot-docker-compose`, springdoc, `compose.yaml`,
  `openapi/`, `e2e-tests/`, Collector in `docs/`.
- `.github/workflows/build.yml` already runs `./mvnw -B -ntp verify` on `ubuntu-latest` (Docker available), so it
  already runs `*IT`; only verify it.
- `docs/antora.yml`: component `irurueta-auth-server`, no `ext.collector`; `docs/package.json` and
  `docs/antora-playbook.yml` have no Collector extension. `.gitignore` already ignores `target/`.
- Conventions (`CLAUDE.md`): Apache 2.0 header on every source file, one package + `@Configuration` per feature,
  AsciiDoc tag comments for docs code, no committed secrets/keys.
- Docker 29.9.2 is available locally for Testcontainers.
