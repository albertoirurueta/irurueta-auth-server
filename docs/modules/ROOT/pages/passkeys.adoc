= Passkeys (WebAuthn)

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

A passkey is a phishing-resistant credential held by the user's device. It works as a passwordless primary sign-in
and as the second factor after a password. The ceremonies are Spring Security's own (`http.webAuthn(...)`); this
server adds the factor registration, the persistence port, the account API and the pages.

== Factor and sign-in

`PasskeyFactor` registers `FACTOR_WEBAUTHN` as a strong primary factor (`amr` value `hwk`), so a passkey alone
satisfies `MfaPolicy`. After a password, the factors merge and `amr` is `pwd`, `hwk` and `mfa`; see
xref:mfa-and-step-up.adoc[].

== Registration and management

`GET`, `PATCH` and `DELETE /api/account/passkeys` (the `id` is the base64url credential id). Deleting one calls
`StepUpGuard` while the account has a confirmed second factor.

== Limitations

* Passkey-first sign-up is not possible: registration needs an authenticated session, so an account starts with
  another primary factor.
* A passkey-only session gets the password `acr`, by design: the passkey is a strong factor but not multi-factor alone
  (user verification is only preferred), so it cannot satisfy a step-up and the user adds a second factor (see
  xref:mfa-and-step-up.adoc[]).
* Spring's relying party operations fix user verification to `preferred`.
* `lastUsedAt` equals `createdAt` until the first use, because Spring's schema requires `last_used`.
