= Implicit flow (legacy demo) and PAR

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

The implicit grant (`response_type=token`) is removed from OAuth 2.1 because the access token travels in the URL
fragment and the browser history. The default server therefore answers it with `unsupported_response_type`, for every
client.

The provider needs an exact registered redirect URI and a `state`, applies the multi-factor policy, issues a short-lived
token restricted to the configured audience and to the requested scopes the client is allowed (the default
configuration gives it one), and never a refresh token. The client has no consent step and no PKCE (a
registration whose only grant type is `implicit` is exempt from the public-client PKCE rule).

[source,java]
----
include::example$auth-server/api/web/src/main/java/com/irurueta/authserver/authorization/api/web/implicit/LegacyImplicitResponseHandler.java[tag=implicit-response-handler]
----

The response is a `302` to `redirect_uri#access_token=...&token_type=Bearer&expires_in=...&state=...` with
`Cache-Control: no-store` and `Referrer-Policy: no-referrer`. An error after the client and redirect URI are validated
is returned as `#error=...&state=...`; before that the request is rejected without a redirect. Every other response (the
authorization code) is delegated to the framework's handler unchanged.
