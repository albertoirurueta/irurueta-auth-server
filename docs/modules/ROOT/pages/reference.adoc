set (organization `albertoirurueta`, project `albertoirurueta_irurueta-auth-server`).

=== Generating the reports locally

`./mvnw verify` writes the raw results (`<module>/target/surefire-reports/`, `failsafe-reports/`, `site/jacoco/`,
`checkstyle-result.xml`, `pmd.xml`, `spotbugsXml.xml` and `coverage/target/site/jacoco-aggregate/`). For the browsable
site exactly as it is published, run:

[source,bash]
----
./mvnw install
./mvnw site site:stage -DskipTests   # written to target/staging
----

The aggregated Javadoc resolves the modules from the local repository, which is why the build runs `install` first.

== Build gates

`./mvnw -B clean verify` fails when any of these fails:

[cols="1,3",options="header"]
|===
|Gate
|Rule

|Checkstyle
|`checkstyle.xml`, `violationSeverity=warning`, test sources included (full Javadoc, `final` parameters, no magic
numbers). Runs at the `validate` phase.

|PMD and CPD
|Static analysis and copy-paste detection, at `verify`.

|SpotBugs
|`threshold=Medium`, `effort=Max`; exclusions only in `spotbugs-exclude.xml`, each with a reason.

|JaCoCo
|80% line and 70% branch coverage on the bundle aggregated by the `coverage` module (unit plus integration tests).
Never lowered: add tests instead.

|Enforcer
|Java `[21,26)`, Maven 3.9 or newer and the per-module `bannedDependencies` rules of the hexagonal layout.

|ArchUnit
|`HexagonalArchitectureTest` in the `boot` module of each application.
|===

== SonarCloud

The `Build and test` workflow runs `./mvnw -B -ntp sonar:sonar` after `verify` when the `SONAR_TOKEN` secret is set. The
project properties (`sonar.organization`, `sonar.projectKey`, `sonar.host.url` and the aggregated JaCoCo report path)
live in the root `pom.xml`. That workflow never deploys anything; only the *Documentation* workflow publishes, and
only the documentation.
