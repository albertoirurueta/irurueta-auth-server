= Installation

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Irurueta Auth Server is an example project, so it is not published as a package. Build and run it from source.

== Prerequisites

* *JDK 21* or newer. The build enforces Java 21 as the minimum.
* *Docker*, for the integration tests (Testcontainers) and for the local services the applications will use.
* Maven is optional: the repository ships the Maven wrapper (`./mvnw`).

== Build and test

[source,bash]
----
git clone https://github.com/albertoirurueta/irurueta-auth-server.git
cd irurueta-auth-server
./mvnw verify
----

`verify` compiles every module, runs the unit tests (`*Test`, Surefire) and the integration tests (`*IT`,
Failsafe), and writes the JaCoCo coverage reports. The current version is `1.0.0-SNAPSHOT`.

The root `compose.yaml` starts PostgreSQL 18 and Mailpit for local development. The integration tests do not use it:
they start their own PostgreSQL container through the `test-support` module (`@PostgresIT`). The `e2e-tests` module
is built last and runs a Playwright sign-in smoke test (`SignInSmokeIT`) against the other modules; Playwright
downloads its Chromium build on first use.

== Run the applications

Run `auth-server` with the `dev` profile: it starts the services of `compose.yaml` through `spring-boot-docker-compose`
(PostgreSQL, and Mailpit on SMTP port 1025 and web UI port 8025), applies the Flyway migrations and seeds a `demo` user
and a confidential `bff` client with generated secrets, which it writes to its log. Export the client secret as
`BFF_CLIENT_SECRET` before starting the `bff`.

WARNING: The `dev` profile data and the compose credentials are throwaway development values. The signing key is
temporarily generated in memory at each start.

Start each application in its own terminal, `auth-server` first. The `dev` profile finds `compose.yaml` at
`../compose.yaml`, relative to the working directory, which `spring-boot:run` sets to the module directory. When starting
the jar or an IDE run configuration from elsewhere, point to the file with
`SPRING_DOCKER_COMPOSE_FILE=<repository>/compose.yaml`.

[source,bash]
----
./mvnw -pl auth-server spring-boot:run -Dspring-boot.run.profiles=dev
./mvnw -pl resource-server spring-boot:run
./mvnw -pl bff spring-boot:run
./mvnw -pl service-client spring-boot:run
----

[cols="1,2",options="header"]
|===
|Application
|Address

|`auth-server`
|http://localhost:9000

|`bff`
|http://localhost:8080

|`resource-server`
|http://localhost:8081

|`service-client`
|No HTTP port: it runs, calls the API and exits.
|===
