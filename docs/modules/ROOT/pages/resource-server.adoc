= Resource server

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

The `resource-server` (port 8081) is hexagonal like `auth-server`: a `Document` (id, title, owner) in `domain`, a list
and a delete use case in `application`, an in-memory repository in `infrastructure/memory` (a real adapter that needs no
schema) and the REST API in `api/web`.

== Token validation

By default tokens are JWTs. The decoder is built from `spring.security.oauth2.resourceserver.jwt.issuer-uri`
(`AUTH_ISSUER`) and only accepts tokens whose `aud` claim lists one of
`spring.security.oauth2.resourceserver.jwt.audiences` (`RESOURCE_SERVER_AUDIENCES`, default `resource-server`). The
application refuses to start when that list is empty, instead of accepting every token. Failures answer with the
RFC 6750 `WWW-Authenticate` challenge (`invalid_token` or `insufficient_scope`).

== Opaque token profile

With the Spring profile `opaque`, the resource server introspects tokens instead. The introspection URI and client
credentials come from the environment variables `AUTH_INTROSPECTION_URI`, `INTROSPECTION_CLIENT_ID` and
`INTROSPECTION_CLIENT_SECRET`, with no defaults. `AudienceRolesOpaqueTokenIntrospector` applies the same audience check
and role mapping, so both variants behave alike.
